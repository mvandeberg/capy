= Buffer Sources and Sinks

This section explains the `BufferSource` and `BufferSink` concepts for zero-copy I/O where the callee owns the buffers.

== Prerequisites

* Completed xref:6.streams/6c.sources-sinks.adoc[Sources and Sinks]
* Understanding of caller-owns-buffers patterns

== Callee-Owns-Buffers Pattern

With streams and sources/sinks, the *caller* provides buffers:

[source,cpp]
----
// Caller owns the buffer
char my_buffer[1024];
co_await stream.read_some(make_buffer(my_buffer));
----

Data flows: source → caller's buffer → processing

With buffer sources/sinks, the *callee* provides buffers:

[source,cpp]
----
// Callee owns the buffers
const_buffer arr[16];
auto [ec, bufs] = co_await source.pull(arr);
// bufs now point into source's internal storage
----

Data flows: source's internal buffer → processing (no copy!)

== BufferSource

A `BufferSource` provides read-only buffers from its internal storage and a `consume` operation to advance past data the caller has used:

[source,cpp]
----
template<typename T>
concept BufferSource =
    requires(T& src, std::span<const_buffer> dest, std::size_t n) {
        { src.pull(dest) } -> IoAwaitable;
        requires awaitable_decomposes_to<
            decltype(src.pull(dest)),
            std::error_code, std::span<const_buffer>>;
        src.consume(n);
    };
----

=== pull and consume Semantics

[source,cpp]
----
IoAwaitable auto pull(std::span<const_buffer> dest);
void           consume(std::size_t n) noexcept;
----

`pull` fills the caller-provided span `dest` with buffer descriptors and await-returns `(error_code, std::span<const_buffer>)`. On return exactly one of the following holds:

* *Data available* — `!ec` and the returned span is non-empty. The descriptors point into the source's internal storage.
* *Source exhausted* — `ec == cond::eof` and the returned span is empty. No more data is available.
* *Error* — `ec` is set and `ec != cond::eof`.

Calling `pull` again without an intervening `consume` returns the *same* unconsumed data. `consume(n)` advances the read position by `n` bytes; the next `pull` returns data starting after the consumed bytes. The descriptors stay valid until the next call to `pull`, `consume`, or until the source is destroyed.

=== Example

[source,cpp]
----
template<BufferSource Source>
io_task<std::size_t> process_source(Source& source)
{
    const_buffer arr[16];
    std::size_t total = 0;

    for (;;)
    {
        auto [ec, bufs] = co_await source.pull(arr);

        if (ec == cond::eof)
            co_return {{}, total};   // Source exhausted

        if (ec)
            co_return {ec, total};

        std::size_t n = 0;
        for (const_buffer b : bufs)  // Process buffers (zero-copy!)
        {
            process_data(b.data(), b.size());
            n += b.size();
        }

        source.consume(n);           // Advance past the bytes we used
        total += n;
    }
}
----

== BufferSink

A `BufferSink` exposes writable buffers from its internal storage. The caller writes directly into them, then commits:

[source,cpp]
----
template<typename T>
concept BufferSink =
    requires(T& sink, std::span<mutable_buffer> dest, std::size_t n) {
        { sink.prepare(dest) } -> std::same_as<std::span<mutable_buffer>>;
        { sink.commit(n) } -> IoAwaitable;
        requires awaitable_decomposes_to<
            decltype(sink.commit(n)), std::error_code>;
        { sink.commit_eof(n) } -> IoAwaitable;
        requires awaitable_decomposes_to<
            decltype(sink.commit_eof(n)), std::error_code>;
    };
----

=== prepare Semantics

[source,cpp]
----
std::span<mutable_buffer> prepare(std::span<mutable_buffer> dest);
----

Synchronous. `prepare` fills `dest` with writable buffer descriptors pointing into the sink's internal storage and returns the sub-span that was filled. An empty returned span means the sink has no space available right now; commit pending data and try again.

=== commit and commit_eof Semantics

[source,cpp]
----
IoAwaitable auto commit(std::size_t n);
IoAwaitable auto commit_eof(std::size_t n);
----

Both await-return `(error_code)`. `commit(n)` finalizes `n` bytes written into the most recent `prepare` buffers and may trigger underlying I/O. `commit_eof(n)` commits a final `n` bytes and signals end-of-stream; after it succeeds, no further operations are permitted. Buffers returned by `prepare` stay valid until the next call to `prepare`, `commit`, `commit_eof`, or until the sink is destroyed.

=== Example

[source,cpp]
----
template<BufferSink Sink>
io_task<std::size_t> write_to_sink(Sink& sink, std::span<char const> data)
{
    mutable_buffer arr[16];
    const_buffer remaining = make_buffer(data.data(), data.size());
    std::size_t written = 0;

    while (buffer_size(remaining) > 0)
    {
        auto bufs = sink.prepare(arr);         // writable space owned by the sink
        if (bufs.empty())
            break;                             // no space available right now

        std::size_t n = buffer_copy(bufs, remaining);
        remaining += n;                        // advance past the copied bytes

        auto [ec] = co_await sink.commit(n);   // hand the bytes to the sink
        if (ec)
            co_return {ec, written};

        written += n;
    }

    auto [ec] = co_await sink.commit_eof(0);   // commit final bytes + signal EOF
    co_return {ec, written};
}
----

== Zero-Copy Benefits

Buffer sources/sinks enable true zero-copy I/O:

=== Memory-Mapped Files

[source,cpp]
----
// A type models BufferSource by satisfying the concept — it does not
// inherit from it.
class mmap_source
{
    char* mapped_region_;
    std::size_t size_;
    std::size_t offset_ = 0;

public:
    io_task<std::span<const_buffer>>
    pull(std::span<const_buffer> dest)
    {
        if (offset_ >= size_)
            co_return {error::eof, {}};  // Exhausted: empty span

        // Hand back a descriptor into the mapped memory—no copy!
        dest[0] = const_buffer(mapped_region_ + offset_, size_ - offset_);
        co_return {error_code{}, dest.subspan(0, 1)};
    }

    void consume(std::size_t n) noexcept { offset_ += n; }
};
----

=== Hardware Buffers

DMA buffers, GPU memory, network card ring buffers—all can be exposed through `BufferSource`/`BufferSink` without intermediate copying.

== Example: Compression Pipeline

[source,cpp]
----
// Compressor provides compressed data via BufferSource
// Decompressor consumes compressed data via BufferSink

task<> decompress_stream(any_buffer_source& compressed, any_write_sink& output)
{
    const_buffer arr[16];

    for (;;)
    {
        auto [ec, bufs] = co_await compressed.pull(arr);
        if (ec == cond::eof)
            break;
        if (ec)
            throw std::system_error(ec);

        std::size_t n = 0;
        for (const_buffer b : bufs)
        {
            auto decompressed = decompress_block(b);
            co_await output.write(make_buffer(decompressed));
            n += b.size();
        }
        compressed.consume(n);
    }

    co_await output.write_eof();
}
----
